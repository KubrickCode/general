## 작업 규칙

- 작업은 항상 애자일하게, 작은 단위로, 의미 있는 변경 단위로 진행한다.
- 급하게 구현하기보다는 항상 버그를 만들지 않고 유지보수하기 쉬운 깨끗한 코드 작성에 집중한다.
- 단일 파일에 코드가 너무 많다고 느껴지면, 먼저 전체 구조를 검토하고 파일을 깔끔하게 분리하는 방법을 파악한다.
- 항상 주변 코드 컨텍스트를 이해하고, 재사용 징후가 보이면 모듈화하여 코드 중복을 피한다.
- 항상 유닛 테스트하기 쉬운 방식으로 코드를 작성한다.
- 복잡한 구현이 필요한 경우, 항상 직접 코딩하는 대신 상용 라이브러리나 도구 사용을 고려한다.

## 코딩 스타일 & 가이드라인

- 가능한 한 코드 효율성보다 코드 가독성을 우선시한다.
- 항상 짧고 간결한 코드를 작성한다. early return 기법을 잘 활용하고, 조건문이나 루프에서 너무 많은 깊이가 생기지 않도록 주의한다.
- 항상 변수명과 프로퍼티명을 간결하면서도 명확하게 유지한다.
- 항상 관심사의 명확한 분리를 유지한다. 그러나 조기 최적화 같은 과도한 분리는 주의한다.
- 주석은 꼭 필요한 경우가 아니면 사용하지 않는다. 주석 없이 이해할 수 있는 읽기 쉬운 코드를 작성하고, 불가피한 비즈니스 로직에만 주석을 포함한다.
- 변수 값은 가능한 한 상수로 분리한다. 매직 넘버 생성을 피한다.
- 루프와 조건문의 깊이는 가능한 한 최소화한다. 아예 피하는 것이 가장 좋다.
- 함수가 3개 이상의 인수를 가질 가능성이 있으면, 항상 객체나 구조체 인수로 만드는 것을 고려한다.
- 캡슐화, 상속, 다형성, SOLID 원칙을 포함하여 적용 가능한 경우 언제든지 객체 지향 프로그래밍(OOP) 원칙을 따른다.

## TypeScript 코딩 가이드라인

- TypeScript를 사용할 때는 any 타입이나 타입 어설션 같은 안전하지 않은 타입 시스템 사용을 가능한 한 피한다.
- 항상 Interface 대신 Type을 사용한다.
- 클래스 밖의 독립 함수에는 화살표 함수를 사용한다. 클래스 내부에서는 화살표 함수 대신 일반 메서드 구문을 사용한다.
